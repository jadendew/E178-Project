Surrogate Model Refresher

Results: Surrogate Model Based Control

Quick Refresher: What the MLP Predicts

As mentioned in the previous sections, for our case the MLP model acts as a fast aerodynamic surrogate capable of taking the local flight condition and control surface deflections and predicts the six aerodynamic coefficients needed by the aircraft dynamics model. It was trained on a sparse data set generated by OpenVSP where it was able to learn the underlying trends in how these coefficients change with respect to these different angles and as as such is able to predict these coefficients for any combination of angles in 3D space even if that combination was not in the original data set.

Input: [α, β, δS, δD] → MLP → Output: [CL, CD, CY, Cl, Cn, Cm]

As a result of this the MLP model also learned how the yaw, pitch, and roll moment coefficients were coupled with the different control surface deflections, which is important considering that the flying wing can only control yaw by also changing its pitch and roll. In practical terms, this means the controller does not need to call any sort of CFD solver during each simulation step. Instead, the trained MLP provides quick coefficient estimates that can be converted into forces and moments. The rest of this results page focuses on what happens when that surrogate model is placed inside the MPC controller.

MLP + MPC Integration

How the MLP is Used Inside the MPC

On a basic level, Model Predictive Control works by repeatedly simulating possible future control actions over a short prediction horizon. At each update, the controller tests candidate control surface commands, predicts the resulting future aircraft states, scores each rollout, and applies the first command from the best sequence. Once this is done, the controller then completes this process for the next time step, and the next, and so on, this achieves control based on the predicted outcome of its underlying model.

The MLP model is incorporated into this framework as the predictive aerodynamic model inside these rollouts. For every predicted future state, the controller computes the local aerodynamic inputs, queries the MLP for coefficient predictions, converts those coefficients into aerodynamic forces and moments utilizing the local pressure and velocity conditions, and advances the dynamics. This is how the controller is predictive, it can evaluate how a given control choice is expected to generate forces and as such how it is expected to change future heading, pitch, and roll, position as well as their rates.

candidate controls → predicted α, β, δS, δD → MLP coefficients → forces/moments → next state → rollout cost

The MPC framework in its current form is not very advanced and serves as a demonstrative example of what this sort of surrogate modeling can be used for. The controller in this case is configured only to control heading to a fixed goal and does not care about its x, y, or z position. In addition, the controller is unable to change thrust values with thrust being set as a fixed number. Finally, the MPC control horizon is fairly short with only a fixed small number of candidate control sequences being considered at every step, this was done to lessen the needed compute power at the cost of severely limiting the controller's abilities. This control result meant to be the “cherry on top”, showing at least one way this type of ML model could be used in a downstream engineering task.

Discussion

From the animation and graphs, it can be seen that the MPC controller is able to fairly accurately control to the desired trajectory with mild levels of oscillation both during the transient and steady state.

An interesting thing to note is that during the transient stage both the pitch and roll angles experience very large oscillations while the yaw oscillations during this time are not as pronounced. This isn't a result of poor damping but rather due to the fact that the MLP solver and as such the MC controller understands very well the coupling between roll,pitch, and yaw, This results in the controller commanding the aircraft to perform a bank and pitch motion to account for the aircraft's poor yaw authority. This appears in the graphs as wild oscillations in both of these angles.

A second interesting behavior is the controller's steady-state response. As shown in the tracking plots, the MPC stays close to the commanded trajectory once the maneuver settles, with the trajectory error generally remaining within around 0.2 degrees. However, the response still contains a small amount of jittery oscillation around the command. This is likely caused by a combination of the controller's short prediction horizon, finite candidate sampling, and the strongly coupled yaw-roll dynamics of the flying wing.

Since the MPC only predicts over a limited horizon and evaluates a finite set of candidate control sequences, small changes in the current state can cause the optimizer to select slightly different control surface deflections from one update to the next. Near steady state, where the remaining errors are very small, these small command changes can be large enough to overshoot the target and then require a correction in the opposite direction. This effect is further amplified by the aircraft's limited direct yaw authority: small heading corrections often require roll and differential surface motion, so even minor heading cleanup can introduce coupled roll, pitch, and yaw motion. This was attempted to be fixed through a number of heuristic changes near steady state such as soft deadbands, a steady-state hold rule, warm-starting, and optional output filtering to reduce these oscillations, however despite these implementations these small oscillations are still present.

Despite these issues the MPC controller still achieves the commanded control goals and serves as a demonstrator as to how this type of MLP based surrogate modeling can be applied to engineering problems.

Discussion

From the data, it can be seen that the MPC and PID controllers are both able to achieve the specified control goal with similar degrees of success. These two controllers however do have a few fundamental differences that demonstrate where the limitations of using this MLP-MCP control scheme lie.

First let's discuss where the MPC does better than the PID. Most of the improvements of the MPC framework can be seen during the initial transient. During this time MLP-MPC controller reaches the commanded heading faster than the baseline PID due to it using a more aggressive coupled maneuver. Since the flying wing has limited direct yaw authority, the controller cannot simply yaw the vehicle to the new heading. Instead, it banks the aircraft and uses the resulting coupled roll-yaw motion to turn. The PID controller however does not do this most likely due to the coupling between yaw, roll, and pitch not being as well defined as in the MPC controller. This goes to show how well the MLP was able to capture the underlying trends of the aerodynamic coefficients respond to control surface deflection and is a testament to its predictive power. This does result in a large pitch overshoot for the MPC controller which is tied to this maneuver since as the aircraft banks and turns, the controller also commands a pull-up-like response to maintain attitude control while redirecting the vehicle. This creates larger initial pitch and roll excursions than the PID controller, but those excursions help the MPC capture the heading command more quickly.

The tradeoff for this is that the MPC is less smooth near steady state. Once the aircraft is close to the commanded heading, pitch, and roll values, the baseline PID appears more naturally damped and settles with less visible jitter. The MPC error also converges quickly, but it retains small oscillations around the command after the main transient has passed. This is likely caused by the lightweight MPC implementation continuing to re-optimize over a short prediction horizon with a finite set of candidate controls, where small state changes near the target can lead to slightly different control surface commands from one update to the next. This would indicate that a more robust implementation of the MPC would be needed to remedy this resulting extra compute needed compared to using the PID controller.

While demonstrating one controller's superiority to another is not the main objective of this project, comparing the two does give us insight as to why a surrogate model MPC framework may be used over a traditional control scheme. This serves as a justification as to why using MLP regression to form a surrogate model has practical applications and provides worthwhile predictive power.

Final Summary

Regression is Key Takeaway, Control is Demonstrative

The central contribution of the project is the aerodynamic coefficient regression model. This controller was added to serve two purposes: to demonstrate the real world engineering applications of using this approach to surrogate modeling and to show the accuracy of the results of our regression.

From the simulation we can see that the MLP-MPC based model was able to accomplish the required control goals and not only that was able to do it to similar fidelity as a traditional PID control framework. This demonstrates the relevance of our results and how with a bit more fidelity added to both the regression and controller, a robust control system could be created using this method.

We can also gauge the accuracy of our regression from the outcome of these simulations. For one the MLP dynamics solver was able to accurately provide predictions of aerodynamic coefficients given control surface deflections that even over a short horizon the MPC controller was able to use it to achieve the required control goal. Not only that, the regression was good enough to capture and predict the coupled relationship between the yaw, pitch, and roll moments that the controller was able to have the aircraft execute a bank and pitch maneuver to overcome its weak yaw control authority.

Overall, the MLP regression was able to successful capture the trends of how the control and body angles of the aircraft influence the aerodynamic forces experienced by the aircraft. It was able to do so while only being trained by a sparse data set with control surface data located only along its principle axes, predicting all combinations of these control surface angles' relationship to these aerodynamic coefficients. Finally, we were able to apply this regression to a real engineering problem creating a controller that was able to accomplish our specified control goals.
